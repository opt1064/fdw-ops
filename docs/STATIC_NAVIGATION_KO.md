# 정적 설비 관통 방지와 검증 범위

## 변경 사항

- MaterialRack_0/1/2(화면에서 세 랙), CantileverRack 및 형제 prim인 보관 파이프를 포함하여 **실제로 표시된 USD 형상**에서 정적 장애물 지도를 만듭니다. 작업대, 고정 설비, 벽, 펜스와 기둥도 포함합니다. 바닥/도색/주행용 충전 패드는 제외하지만 충전 타워와 범퍼는 포함합니다.
- USD 부모 변환, 회전, 스케일, metersPerUnit을 적용한 월드 경계로 XY 보수적 AABB를 구성합니다. 임의 affine 변환은 고정 설비 측정에 반영합니다. 이동 AMR의 부모는 수평·양의 균일 XY 스케일만 지원하며, 기울임/반사/비균일 XY 스케일/전단은 안전한 회전 envelope를 보장할 수 없어 실행을 거절합니다.
- 차체와 허용 적재물의 외접 원 중 큰 크기에 안전 여유를 더합니다. 편심 적재물의 돌출도 포함하며, 빈차 접근과 주차 복귀에도 동일한 최대 envelope를 예약합니다. 실제 부품 메시가 허용 XY/높이를 넘거나 측정할 수 없으면 해당 이송을 보류합니다.
- 회전 전에 현재 자세를 검사하고, 모든 이동 구간을 분석적으로 검사합니다. 큰 dt로 장애물을 건너뛰어도 관통할 수 없습니다. 단순한 중심점/끝점 샘플링 검사가 아닙니다.
- 고정된 공유 lane이 랙을 통과하던 경로를 폐기하고 장애물 외곽 visibility graph로 경로를 찾습니다. 차량 간 점유는 기존처럼 한 번에 한 AMR만 이동하는 보수적 예약을 유지합니다.
- 기존 소재 도크 `(10.3, 4.9)`와 작업대에 너무 가까운 도크를 그대로 사용하지 않습니다. 시작 시 원래 도크에서 최대 4m 안의 free-space 후보와 주차 베이를 정적으로 검증하여 선택하고, 같은 좌표를 차량·서비스/주차 마커에 사용합니다. 랙과 설비의 배치를 옮기지 않습니다. 실제 선택 좌표와 장애물 출처는 로그에 남습니다.
- 경로 없음, 잘못된 지도, 충돌하는 도크/초기 위치, 지나치게 큰 지도는 장애물 ID와 함께 중단합니다. 완료 처리나 순간이동으로 우회하지 않습니다. 실행 중 보류는 부품 보유·도크 점유·차량 예약을 유지합니다.

## 실행 및 안전한 갱신

현재 실행 중인 데모를 먼저 정상 종료한 후, 기존 검토 checkout에서 변경 사항과 브랜치를 확인하십시오. 로컬 수정 사항이 있으면 아래 갱신을 실행하지 않습니다. 강제 reset 또는 강제 push는 사용하지 않습니다.

```bash
git status --short
git branch --show-current
# 로컬 수정 사항이 없고, 현재 브랜치가 기존 검토용 브랜치인 것을 확인한 후:
git fetch origin fix/fdw-quality-disposition-base-pose
git merge --ff-only FETCH_HEAD
```

CPU 회귀 테스트는 별도 일반 Python 가상환경에서 실행합니다. `usd-core`는 실제 OpenUSD in-memory 변환/형상 검사에 쓰는 개발 의존성이며 Isaac Python에 새로 설치할 필요가 없습니다.

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

운영 논리/주행 데모:

```bash
"$ISAACSIM_PYTHON_EXE" scripts/run_poc1_level2_2.py --gui --real-robot --realtime --keep-alive --motion-execution schematic
```

## 검증과 제한

- 정확한 세 랙 좌표, Cantilever 및 파이프 돌출, 큰 편심 적재물, 변환된 부모와 stage 단위, 경계·도크·spawn 충돌, 경로 없음, 두 AMR 반복 작업과 주차 복귀 회귀를 추가했습니다.
- 정적 도형 검사 및 실제 OpenUSD CPU 테스트를 수행합니다. **Isaac GUI/PhysX, 실제 FANUC 파지·TCP 도달, 접촉/동역학 또는 하드웨어를 실행하여 검증한 것은 아닙니다.**
- 표시된 현재 USD 메시 경계는 현장 측량/충돌 인증을 대체하지 않습니다. 지도는 시작 시 고정된 배치를 기준으로 하므로 설비를 옮기면 시뮬레이션을 재시작하여 지도를 다시 측정해야 합니다. 동적으로 움직이는 사람/설비와 팔의 미래 swept volume은 이 정적 AMR 지도 범위 밖입니다.
- 자동 선택된 서비스 도크는 논리적 부품 전달 지점입니다. 로봇 팔이 실제로 도달할 수 있다는 의미가 아닙니다. 기본 `verified` 모드는 미검증 파지 어댑터 때문에 계속 보류하며, `schematic`은 물리 파지·용접 성공을 뜻하지 않습니다.
- Discrete 모드는 별도 논리 좌표계입니다. 실제 공장 정적 지도를 검사했다는 주장으로 사용하지 않습니다. GUI에서는 USD 측정 실패 시 빈 지도나 fixture로 대체하지 않습니다.

### 이 변경의 CPU 검증 기록 (2026-10-06)

- 전체 337 tests 및 24 subtests 통과. 최종 Git tree를 별도 깨끗한 디렉터리로 추출하여 같은 테스트를 재실행합니다.
- 실제 OpenUSD 엔진의 in-memory 기본 장면 fixture에서 41개 정적 그룹과 두 AMR의 4회 이송/주차 복귀를 검사합니다. 이 fixture는 기본 SceneBuilder 절차적 형상을 사용하며, Isaac에서 외부 실 로봇 자산을 모두 로드한 실기 검증을 뜻하지 않습니다.
- 기본 envelope의 fixture 서비스 도크: 소재 `(13.05, 4.9)`, 용접 `(25.1, 8.95)`, 검사 `(34.6, 4.65)`. 실제 로드 자산 경계가 다르면 선택 좌표가 달라지거나 시작이 거절될 수 있습니다.
- 같은 전체 fixture에서 2.4×1.0m envelope는 연결된 경로를 찾지 못해 안전하게 거절됩니다. 랙을 옮기거나 더 작은 envelope로 축소하지 않습니다.
- 기존 6개 smoke, compileall, diff 검사 통과. Discrete 예시: 출하 1, 격리 2, 미완료 0. Discrete 결과는 정적 공장 지도 검증이 아닙니다.

# AMR·공정 모션 동기화 수정

## 현재 검증 범위

이 변경은 **CPU 논리/기하 회귀**이며 Isaac Sim GUI, PhysX 접촉, 실 FANUC의 도달·파지·용접 검증을 대신하지 않습니다. FANUC용 URDF, Lula/RMPflow 설명 파일, 관절 순서/한계, home, TCP, 그리퍼 접촉·부착을 임의로 만들어 넣지 않았습니다. KUKA 질량·관성 경고도 별도 자산 검증 과제로 남아 있습니다.

## 두 실행 선택

- 기본 `--motion-execution verified`: 검증된 물리 파지 어댑터가 없으면 AMR이 도크에서 부품을 보유한 채 대기하고 원인을 로그로 알립니다. 현재 제공되는 컨트롤러에는 검증된 파지 어댑터가 없으므로 로봇이 있는 용접 셀의 픽업은 성공 처리되지 않습니다. timeout도 성공/출하가 아닙니다.
- 명시적 `--motion-execution schematic`: **운영 절차 도식 데모**입니다. AMR 위치·교통과 공정 게이트를 실행하지만 팔에 파지 동작을 명령하거나 목표 TCP를 실제 파지로 표현하지 않습니다. 적재 부품은 도크에서 대기한 뒤 논리 배치 완료 시 작업대에 재배치합니다. 용접도 레시피와 같은 시간의 논리 타이머이며 스파크는 꺼집니다. 이는 실제 로봇 집기/용접 성공의 증거가 아닙니다.
- discrete 또는 로봇 없는 셀: 명시적 논리 핸드오프이며 로봇 모션 의존성이 없습니다. 품질 검사와 PASS 출하/FAIL·REWORK 격리 규칙은 유지합니다.

실제 GUI 확인을 할 기존 Isaac 전용 Python 환경에서 운영·교통 데모:

```sh
"$ISAACSIM_PYTHON_EXE" scripts/run_poc1_level2_2.py --gui --real-robot --realtime --keep-alive --motion-execution schematic
```

기본 안전 동작(미검증 물리 픽업 보류) 확인:

```sh
"$ISAACSIM_PYTHON_EXE" scripts/run_poc1_level2_2.py --gui --real-robot --realtime --keep-alive --motion-execution verified
```

`--single-amr-demo`는 검사를 생략하므로 전체 품질/격리 검증에는 사용하지 않습니다.

## AMR 모델

- MaterialCell의 position과 heading이 유일한 위치 기준입니다. 최초 USD 배치와 매 프레임 렌더링 모두 같은 값을 씁니다.
- 작업 배정은 현재 위치에서 출발하는 빈차 이동, 소스 적재, 목적지 적재 이동, 픽업 대기, 전용 주차 복귀로 구분됩니다. 명령 소스로 순간이동하지 않습니다.
- 도크 점유는 픽업 대기와 출발까지 유지합니다. 공유 통로는 보수적으로 한 차량에 예약하고 다른 차량은 분리된 주차/대기 베이에 머뭅니다. 병렬 처리량보다 재현 가능한 안전한 순서를 우선합니다.
- 회전 방향과 무관한 차체 외접 반경 및 경로의 swept-footprint 검사로 차량 간 간격을 보수적으로 계산합니다. CPU 모델의 기본 최소 차체 크기는 1.2×0.8m, 여유는 0.15m입니다. GUI 씬 구성 시 로드된 USD의 월드 바운딩박스를 차체 원점 기준으로 측정해 기본값보다 작지 않은 공통 외접 크기로 주차·통로를 다시 계산합니다. 측정이 안 되면 운송을 시작하지 않습니다. simulation의 `amr_footprint_size`, `amr_clearance_m`으로 더 보수적인 최소 크기·여유를 지정할 수 있습니다. 이 USD 측정 경로는 CPU API 대역 검증이며 실제 Isaac 자산으로 확인은 아직 필요합니다.
- xform 기반 운동 모델이며 물리 주행/바퀴 접촉 또는 모든 공장 설비에 대한 경로 충돌회피를 검증한 것은 아닙니다. Isaac GUI에서 실제 메시, 주차 베이, 정적 설비 간 여유를 별도 확인해야 합니다.

## 동기화와 실패 처리

- 수령한 부품을 배치 대기 상태로 보관합니다. 부품 ID와 이송 명령 ID가 같은 배치 완료만 공정 시작을 해제합니다.
- 공정 모션 완료는 부품 ID와 가공 명령 ID에 연결합니다. 오래된/중복 콜백은 다음 부품을 해제할 수 없습니다.
- 논리 레시피 시간과 모션 완료를 모두 만족해야 출력 준비가 됩니다. 목표 순서: placement_done ≤ START_WELDING ≤ motion_done ≤ output_ready.
- 실패 또는 timeout은 미완료/고장으로 남기며 성공 이벤트나 부품 출력을 만들지 않습니다.
- backend 로그는 실제 선택된 backend를 표시합니다. heuristic의 관절 연출, joint readback, 목표 TCP는 실제 도달/파지/충돌 안전의 증거가 아닙니다.
- 측정 가능한 초기 관절값을 보간 시작점으로 사용하고, 미검증 FANUC home를 새로 정의하지 않습니다.
- 스파크는 실제 용접 목적의 검증된 동작 단계에만 허용합니다. 픽업 또는 schematic 타이머에서는 생성하지 않습니다.
- 검사 KPI 표시는 최종 누적 합격률 `last`와 누적 스냅샷 평균 `avg`를 구분합니다.

## GUI 후속 체크리스트

1. 두 AMR의 초기 차체 간격, 빈차 소스 접근, 정확한 도킹 끝점과 heading.
2. 여러 작업에서 도크 대기/출발/주차 복귀 및 실제 USD 차체/공장 설비 간 여유.
3. schematic 표시와 부품 재배치가 물리 파지로 오해되지 않는지.
4. verified 모드에서 미검증 FANUC 픽업이 성공으로 넘어가지 않는지.
5. 실 모델 관절 이름·순서·한계와 TCP·그리퍼 접촉을 검증한 별도 어댑터가 준비된 후 실제 파지/도달/용접 검증.

CPU 회귀 결과는 PR의 최종 검증 기록을 참고하십시오. GUI 체크리스트는 아직 실행하지 않았습니다.

## CPU 검증 기록 (2026-10-06)

- Python 3.12 전체 회귀: 212 tests, 24 subtests 통과.
- 기존 6개 smoke 스크립트, compileall, git diff --check 통과.
- 실제 Isaac 없이 fake scene/controller를 연결한 전체 파이프라인에서 두 AMR 위치·heading·간격과 배치→시작→모션완료→출력 순서 검증.
- stale/duplicate/실패/timeout acknowledgment, 숫자 NaN/Inf/음수 입력, 수신 셀 누락/소실 시 부품 보유 및 fail-closed 동작 검증.
- 기본 discrete 시나리오: 출하 1, 격리 2, 미완료 0. 최종 합격률 0.333, 누적 스냅샷 평균 0.278. 검사 노이즈 때문에 경계 판정은 실행마다 달라질 수 있습니다.
- 빈차 이동·회전·주차 복귀 및 공유 통로 직렬화가 포함되어 기본 시나리오 시뮬레이션 시간이 약 415초로 늘었습니다. 실제 검증 이전 처리량 최적화보다 보수적 순서를 우선합니다.
- 독립 검토에서 발견한 비정상 AMR 속도값과 부품 ID 없는 지연 명령 재생 문제는 수정 후 회귀 검증했습니다.
- Isaac GUI/PhysX/실 로봇 하드웨어는 실행하지 않았습니다.
